# dev.mihureducation.com: host HTTPS edge

Prepared configuration, NOT a deployment. Companion to #302 and image-build PR #430.
This changes the staging canonical public URL; the SSH tunnel remains a diagnostic
path, but links generated by the API now target dev.mihureducation.com.

Topology: browser → host Caddy :443 (public CA) → 127.0.0.1:8443 (verified internal
CA, TLS name localhost) → container Caddy → frontend → API. Only the host edge has
public ACME egress. The Docker network remains internal and its sole published port
remains loopback-only. No insecure certificate bypass or Docker socket mount.

## Prerequisites

Complete the parent staging README isolation inventory first, including host services,
ports 80/443/2019, mounts and credentials. If another web server or production service
exists, STOP; do not overwrite its configuration. This guide assumes a dedicated
Ubuntu/Debian staging host and the official Caddy systemd package with user/group caddy.
Install from https://caddyserver.com/docs/install for the verified OS. Use a current
Caddy version supporting tls_trust_pool file and validate before activation.

Keep DNS directly pointed at staging (DNS-only, no CDN/reverse proxy). The IP allowlist
uses actual peer IPs, not spoofable forwarded headers. Add A dev → staging IPv4; add
AAAA only if IPv6 routing/firewalls are verified. Leave other DNS records unchanged.

Preserve restricted SSH. Permit public TCP 80/443 for ACME issuance/renewal; HTTPS
application access is independently denied except for the configured owner/QA IPs.
Port 80 only serves Caddy's challenge/redirect handling. Keep 2019 loopback-only and
8443/8080/8000/8001/5432/6379 externally blocked on IPv4 and IPv6. No QUIC/UDP rule is
required. Do not blindly replace firewall rules. Keep outbound DNS and ACME HTTPS
available to the host, not the internal application network.

## Prepare the verified upstream

Deploy the reviewed staging release using the parent README and control.py first.
Use only synthetic identities. From the clean root-owned checkout, extract ONLY the
public root certificate (never the CA key) from the fixed project:

```bash
sudo install -d -o root -g caddy -m 0750 /etc/caddy
sudo docker --host unix:///var/run/docker.sock compose \
  --project-name mihur-staging --env-file /etc/mihur-staging/release.env \
  -f deploy/staging/compose.yml cp \
  proxy:/data/caddy/pki/authorities/local/root.crt /etc/caddy/mihur-staging-root.crt
sudo chown root:caddy /etc/caddy/mihur-staging-root.crt
sudo chmod 0640 /etc/caddy/mihur-staging-root.crt
sudo openssl x509 -in /etc/caddy/mihur-staging-root.crt -noout -subject -fingerprint -sha256
sudo curl --fail --show-error --cacert /etc/caddy/mihur-staging-root.crt \
  --resolve localhost:8443:127.0.0.1 https://localhost:8443/healthz
```

Run control.py preflight before extraction; confirm project/container identity and
compare the certificate fingerprint against the verified container's public certificate.
Do not import this CA into the system-wide trust store: trust is scoped to this upstream.
If the CA changes unexpectedly, stop and investigate instead of copying a replacement.

## Install the host configuration

Preserve any existing staging-only Caddy config for rollback in a root-only directory.
Do not overwrite foreign configurations. Copy host/Caddyfile to /etc/caddy/Caddyfile
and qa-allowlist.caddy.example to /etc/caddy/mihur-qa-allowlist.caddy, root:caddy 0640.
Replace documentation IPs in the installed allowlist with your and Muse's actual
public addresses. Never commit those addresses or credentials. Missing allowlist or
CA files must block validation; the example allows no ordinary public client.

```bash
sudo -u caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl enable --now caddy
sudo systemctl reload caddy
sudo systemctl status caddy --no-pager
```

Only execute activation after DNS/firewall/allowlist/CA verification. The host Caddy
obtains and renews the domain certificate. Do not manually copy its private keys.
No basic auth is added, so application Authorization headers remain available to the
application. Requests outside the QA allowlist receive 403. Do not broaden access for
families until separate privacy, application-security and owner release gates pass.

## Verification and measurements

From an allowed QA machine, without -k:

```bash
curl --fail --show-error https://dev.mihureducation.com/healthz
curl --fail --show-error https://dev.mihureducation.com/backend-health
```

From a genuinely different, unlisted network, expect 403; spoofing X-Forwarded-For
must not grant access. Verify port 8443 is unreachable externally. Muse checks
registration/login, secure cookies, redirects, generated links, WebSockets (where
applicable), child/session isolation and browser journeys using synthetic accounts.
Check incorrect/missing upstream CA fails validation or yields a TLS error/502 in a
local test setup; never treat an HTTP response as proof that TLS was verified.

The two reverse proxies can collapse client IP attribution downstream. Do not claim
per-user IP throttling or abuse controls validated until Muse/AppSec tests the full
chain; do not broadly trust forwarded headers to solve this. Edge IP restrictions
remain based on the direct TCP peer. No CDN is supported by this baseline.

Include host Caddy in memory/CPU measurements (`systemctl show caddy -p MemoryCurrent`
and process metrics), in addition to control.py metrics. The old 1152 MiB container
budget EXCLUDES host Caddy; 2 GB feasibility remains unmeasured. Check idle and 1/3
synthetic sessions, swap, OOMs, restarts and disk growth. Stop on the parent runbook's
resource thresholds. Do not upload raw logs containing URL tokens or credentials.

## Rollback

For exposure/TLS trouble, `sudo systemctl stop caddy` closes the host edge while
leaving staging data intact. Keep SSH. Restore only the saved staging edge config,
validate, then start/reload after diagnosis. Application/schema rollback follows the
parent README; never delete volumes, CA storage, databases or downgrade schema.
Reverting PUBLIC_BASE_URL requires a reviewed clean release, not a dirty VPS edit.

Reference: https://caddyserver.com/docs/caddyfile/directives/reverse_proxy
