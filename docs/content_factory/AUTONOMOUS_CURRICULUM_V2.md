# Mihur Autonomous Curriculum Factory V2 — phase 1

## What this PR delivers

This PR deliberately starts a **new V2 bounded slice** without adding more hard-coded
course choices to the V1 factory PR #484.

`scripts/curriculum_program_v2.py` provides:
- Parsing a broad natural-language Ontario mathematics goal into a program spanning
  an explicit grade range (1–12).
- Durable, resumable SQLite program and work-unit records with deterministic stable
  IDs, deduplicated imports and audit history. SQLite is an **offline development
  prototype**, not the production multi-tenant PostgreSQL orchestration database.
- Unauthenticated, caller-claimed official source manifest import for **offline planning only**. Grade 10–12 pathways and
  their course identities must be verified; we do not invent one generic course
  per grade.
- Next eligible unit in source/grade order; fail-closed state transitions with
  optimistic version checking.
- Explicit separation of `PROTOTYPE_REVIEW_RECORDED` *planning status* from actual reviewer
  authentication, scorer registration, runtime activation, staging or deployment.

## Example usage

```bash
python -m scripts.curriculum_program_v2 --database /tmp/mihur-v2.db goal \
  'I want the full Ontario mathematics curriculum, Grades 1-12'
```

The result says `AWAITING_OFFICIAL_SOURCE_INVENTORY` with zero units until a
manifest of expectations and course versions is imported with a caller-claimed
source review for offline planning only. The `import-source-manifest` command is a **prototype trusted-operator
interface**; its manifest metadata, including reviewer identity and evidence URL,
is not cryptographically authenticated. An untrusted party could fabricate those
fields; therefore **do not deploy it as an automated approval gate**.

Next (only after Security/Architecture approval):
1. Store signed, source-revision-scoped standards manifests in production
   PostgreSQL with reviewer principal/capability verification and provenance.
2. Expand program parser to jurisdictions/grades/courses through constrained
   AI goal analysis with structured validation and human scope approval.
3. Add durable leased workers, retries, concurrency quotas, cancellation,
   bounded resource budgets, audit logs, and anti-duplicate task claims.
4. Wire actual model research/design agents, licensing checks and exact
   math verification in isolated execution; never treat LLM output as oracle.
5. Keep truly independent reviewer agents/humans isolated from authoring,
   with issue/PR evidence and conditional rework.
6. Produce founder-facing approvals and summary. Do not seed, activate or
   publish questions from planning-state transitions.

## Production safety

This prototype never calls an LLM or browser, performs external research,
creates a PR from content, dispatches an agent, accesses learner records,
grants scoring modes, or deploys. `PROTOTYPE_REVIEW_RECORDED` here is a state-machine word,
**not** verified independent source/content acceptance or release authority.
Existing Content Factory PR #484 remains independently reviewable.

## Phase 1b: bounded worker claim and stale-worker fencing

`claim_next` now atomically selects an eligible work unit (caller-claimed source review for offline planning only),
records its lease owner, expiration and monotonically increasing fencing
token, and enforces a configurable retry budget. Concurrent claimers
using separate SQLite connections cannot claim the same live unit.
`complete_claim` accepts only an unexpired claim with matching owner and
token, records a review-required audit event and releases its claim.
It never marks independent reviewer acceptance or activates content.

These functions are **proof-of-mechanism**, not unattended worker execution.
They have no model runtime, no source acquisition, no parallel PostgreSQL
worker transaction semantics and no durable task scheduler process. Expired retry-exhausted work transitions to audited `BLOCKED_RETRY_EXHAUSTED`. The `status` CLI exposes affected units for manual intervention.

Source-review approval in this prototype is metadata provided to the import
function, not independently authenticated authorization. Production worker
and reviewer boundaries must be established before moving this into Mihur's
real service. No actual questions are generated by this change.

## Architecture correction: trust, provenance and identity

- Imported manifest `verification_state` is explicitly `CLAIMED_SOURCE_REVIEWED_UNAUTHENTICATED`, not accepted Standards evidence. All reviewer labels and HTTPS evidence URLs are untrusted claims. No worker/external client may treat imported metadata as authenticated review or execution permission.
- Reimports compare exact persisted official source URL, version, claimed reviewer and review evidence; conflicts reject transactionally rather than silently ignoring changed provenance.
- The `PROTOTYPE_REVIEW_RECORDED` state is not independent Math, Pedagogy, Standards, Security or Muse approval. Exported approval, execution and activation authority remains false.
- `unit-` IDs are curriculum expectation work units, **never canonical math skill/atom IDs**. No canonical identity, attempt credit, aliases, or mathematical mappings are created. A scored attempt requires exactly one independently accepted primary atom; composite ALL_OF reporting cannot yield double mastery credit.
- `python -m scripts.curriculum_program_v2 --database /tmp/mihur-v2.db status --program-id <id>` reports retry exhaustion. This remains offline SQLite, not PostgreSQL production durability.
- No autonomous model workers, source research, family/learner access, review authentication, content activation, deployment, or authorization exists in this PR.
